# Library data model

`folio-library` is an optional SQLite/index foundation. It is not required by
Core conversion and is not a Reader database.

## Identity and authority

`BookMetadata` is the Library's durable metadata projection of Core inspection.
It contains title, sort title, subtitle, language, publisher, publication date,
description, authors, series/index, tags and identifiers. Core remains the
format/semantic authority; Library does not rewrite source semantics.

Book and file records have both integer local IDs and UUIDs. A `StorageRoot`
owns a user-selected root path. A `FileVariant` stores a safe relative path,
format ID, size, mtime, optional BLAKE3 content hash, origin, source variant,
state and last-seen time. Origins are `scan`, `conversion` and `import`;
states are `present`, `missing`, `duplicate` and `error`.

People, series, tags and identifiers use normalized link tables. Conversion
records link source/output variants, target format and status without storing
the generated bytes in SQLite.

## Schema

The current schema version is `2`. Migration 1 creates the durable entities,
relationships and indexes; migration 2 creates the rebuildable FTS5 search
table. Schema version is independent from product `0.1.0`.

The current tables are `library_meta`, `storage_roots`, `books`, `people`,
`book_people`, `series`, `book_series`, `tags`, `book_tags`,
`book_identifiers`, `file_variants`, `file_metadata`, `conversions`,
`schema_migrations` and the rebuildable `library_search` FTS table.

## Scanning and synchronization

The scanner uses Core inspection and the shared format registry. It must not
duplicate parser logic or store Semantic IR/resource BLOBs. Query methods use
bounded `QueryBudget` values and return explicit pagination/search results.

Metadata synchronization is transactional. A failed database commit is an
error, not a successful file synchronization. Missing and duplicate files are
retained as state so a later scan can explain what changed.

## Contract versions

- Product: `0.1.0`.
- Core ABI: `1`.
- Inspection contract: `folio-core-inspection-v1`.
- Library schema: `2`.

These versions change independently and are recorded in the final audit.
